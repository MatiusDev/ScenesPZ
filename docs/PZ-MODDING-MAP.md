# Project Zomboid — Modding Map (Build 42)

Reference sheet: where files live on disk, what each folder accepts, and what you can
actually build in each one. Sources: [PZwiki Mod structure](https://pzwiki.net/wiki/Mod_structure),
[PZwiki mod.info](https://pzwiki.net/wiki/Mod.info). Verified against stable 42.20.0.

---

## 1. Disk layout — three different "mod" locations, do not confuse them

| Path | What it is | Use it for |
|---|---|---|
| `steamapps/common/ProjectZomboid/` | Game install. `media/` here is vanilla content. | **Read only.** Reference for vanilla scripts/Lua. |
| `steamapps/workshop/content/108600/<id>/` | Mods downloaded from the Workshop. Folder name = Workshop id. | Read only. Reference for how others did it. |
| `~/Zomboid/` | User cache dir (Linux/macOS: `$HOME/Zomboid`, Windows: `%USERPROFILE%\Zomboid`) | **This is where you work.** |

Inside `~/Zomboid/`:

```
~/Zomboid/
├── mods/            # manual install of mods. NOT for development.
├── Workshop/        # ← develop here. required to use the in-game uploader.
├── Lua/             # runtime state written by mods (e.g. Lua/bandits/*.txt)
├── Saves/
├── console.txt      # ← your log file. this is your print() output and your stack traces.
└── logs/
```

**Rule that will bite you:** two copies of the same mod id (one in `mods/`, one in
`Workshop/`, one subscribed on Steam) clash and silently overwrite each other. Symptom:
you edit a file, nothing changes in game. Keep exactly one copy, in `Workshop/`, and
**unsubscribe from your own mod on Steam** while developing.

## 2. The Workshop project folder

```
~/Zomboid/Workshop/MyProject/          ← git repo root lives HERE
├── Contents/                          ← the only thing uploaded to Steam
│   └── mods/
│       ├── MyMod1/                    ← one shippable mod
│       └── MyMod2/                    ← optional/extra mods in the same upload
├── workshop.txt                       ← generated by the in-game uploader
├── preview.png                        ← 256x256, the Workshop thumbnail
├── .git/  .vscode/  README.md  tools/ ← ignored by the game, never uploaded
```

Anything outside `Contents/` is invisible to both the game and Steam. That is where
your git history, build scripts, source PSDs and notes go.

## 3. Inside a single mod (Build 42)

```
MyMod1/
├── common/              ← MANDATORY (mod is not detected without common/ or a version folder)
│   └── media/           ← heavy, version-independent assets
├── 42/                  ← version folder: code + manifest for game version 42.0+
│   ├── mod.info
│   ├── poster.png
│   ├── icon.png
│   └── media/
├── 42.12/               ← optional: overrides for 42.12+ players
└── media/               ← Build 41 only. B41 and B42 structures coexist without clashing.
```

Load order: `common/` first, then the **closest version folder ≤ the running game
version** (it overwrites same-path files from common).

Version folder naming — the patch number is ignored:

| Folder | Treated as |
|---|---|
| `42` | 42.0 |
| `42.1` | 42.1 |
| `42.0.5` | 42.0 |
| `42.1.5` | 42.1 |

Split rule: big binary assets (models, textures, anims) → `common/`. Lua and `mod.info`
→ version folders, because those are what break between game versions.

## 4. `media/` subfolders — what goes where

| Folder | Format | What you can build there |
|---|---|---|
| `lua/client/` | `.lua` | UI, keybinds, rendering, anything the local player sees. Runs on each client. |
| `lua/server/` | `.lua` | World state, spawning, loot, NPC logic. Runs on the host (also in singleplayer). |
| `lua/shared/` | `.lua` | Constants, helper libs, things both sides need. Loaded first. |
| `lua/shared/Translate/` | `.txt` | Localization files, one folder per language code. |
| `scripts/` | `.txt` | **Declarative item/vehicle/recipe definitions.** No Lua needed. Start here. |
| `clothing/` | `.xml` | Clothing item defs (one XML + GUID each) and `clothing.xml` outfit manager. |
| `textures/` | `.png` | Item icons, tile textures, model skins. |
| `ui/` | `.png` | Images used by UI widgets. |
| `sound/` | `.ogg`/`.wav` | Sounds. FMOD `.bank` files cannot be loaded or overridden from mods. |
| `models_X/` | `.x`/`.fbx` | 3D models. |
| `anims_X/` | — | Animation files. |
| `AnimSets/` | — | Animation triggers/parameters. |
| `maps/` | — | Custom map cells + `spawnpoints.lua`. |
| `texturepacks/` | `.pack` | Tile sprite packs (built with the official mapping tools). |

Same relative path = override. Dropping `textures/Item_Axe.png` in your mod replaces the
vanilla icon. This is how retexture mods work, and how you accidentally break other mods.

**Linux is case-sensitive.** `common`, not `Common`. `mod.info`, not `Mod.info`.

## 5. `mod.info`

Plain text, key=value, one per line. Only `name` and `id` are strictly required.

```ini
name=The Last of Us — Factions
id=tlouFactions
author=matiusdev
description=WLF, Seraphites and FEDRA clans for the Bandits framework.
poster=poster.png
icon=icon.png
require=\Bandits2
```

- `id` must be globally unique — it is the collision key across every mod installed.
- `require=` auto-enables dependencies when your mod is enabled. Build 42 syntax uses a
  leading backslash (`\Bandits2`); Build 41 does not (`Bandits2`).
- Watch for a hidden `.txt` extension on Windows.

## 6. Where to write code, by ambition level

| I want to… | Touch | Lua needed |
|---|---|---|
| Add an item, weapon, recipe, vehicle | `media/scripts/*.txt` + `textures/` | none |
| Add clothing | `media/clothing/*.xml` + `textures/` | none |
| Add an NPC faction (Bandits addon) | `common/bandits/{bandits,clans}.txt` | none |
| Change game behavior, spawns, events | `media/lua/server/` | yes |
| Add UI, HUD, menus | `media/lua/client/` + `ui/` | yes |
| New map | `media/maps/` + mapping tools | some |

Lua in PZ is event-driven — you register callbacks on the global `Events` table:

```lua
-- 42/media/lua/client/HelloPZ.lua
Events.OnGameStart.Add(function()
    print("hello from my mod")            -- lands in ~/Zomboid/console.txt
    getPlayer():Say("mod loaded")
end)
```

There is no hot reload for most things: edit → restart the game (or reload the save).
`console.txt` is the only real debugger you get, so `print()` generously.

## 7. This workspace

```
PZ/
├── docs/PZ-MODDING-MAP.md          ← this file
├── tools/workshop.py               ← Steam Workshop CLI (see below)
├── tools/watchlist.txt             ← mods we track
└── mods/TLOUProject/               ← the mod, laid out as a Workshop project
    └── Contents/mods/TLOUFactions/
        ├── 42/mod.info
        └── common/bandits/{clans.txt,bandits.txt}
```

Go live once Steam + PZ are installed — symlink so git stays here and the game sees it:

```bash
ln -s ~/Docs/Workspace/PZ/mods/TLOUProject ~/Zomboid/Workshop/TLOUProject
```

Workshop CLI (no API key needed for `details`/`watch`):

```bash
./tools/workshop.py watch                            # subs + last-update on tracked mods
./tools/workshop.py details 3268487204
export STEAM_API_KEY=...                             # steamcommunity.com/dev/apikey
./tools/workshop.py trending --tag "Build 42" --n 30
./tools/workshop.py search "faction" --tag "Build 42"
```
